# 검증된 랜덤 스테이지 구현

`tile-engine.js`가 seed로 문제와 해법을 만들고 검증한다. `index.html`은 검증을 통과한 결과만 사용한다. 외부 패키지나 서버는 필요 없다.

## 플레이 동작

- 첫 문제와 이후 문제는 새 seed를 사용한다. 상단 섞기 버튼과 성공 후 다음 버튼으로 새 문제를 만든다.
- 다시 시작은 현재 seed와 문제를 유지한다. 되돌리기도 유지한다.
- `index.html?seed=42`로 첫 문제를 재현할 수 있다. React 통합본에서는 `/tile-fit?seed=42`를 사용한다.
- 기존의 직접 도구 조작, 스냅, 제거 미리보기, 자동 맞춤과 물리적 벽 충돌을 유지한다.
- 힌트는 생성된 해법의 재단선이다. 증명서나 seed 설명을 게임 화면에 추가하지 않는다.

펜은 이후 오른쪽 아래 토글 버튼과 직접 드래그 입력으로 변경했다. 가이드 없는 자유곡선도 지원하며, 기존 증명 해법은 가이드에 따라 그대로 재현된다. [펜 입력](pen-input.md)을 참조한다.

후속 변경으로 같은 타일 세 장과 삼각자를 제공한다. 세 장 모두 동일한 검증 해법으로 재단·완료할 수 있으며, 본뜨기 기능은 선택 사항이다. [세 타일과 두 종류의 자](tile-workbench.md)를 참조한다.

## 생성 범위와 종료

현재 문제군은 **위쪽에 벽이 있고 아래쪽으로 열려 있는 직각 높이 프로필**이다. 임의의 동굴·구멍·사선 지형을 생성하는 기능은 아니다. 플레이어가 직접 사선을 긋는 조작은 계속 지원한다.

280×280 재료 좌표에서 2~4개 구간의 폭과 벽 높이를 정한다. 구간 폭은 최소 44칸, 높이는 0 또는 28~140칸이며 이웃한 높이는 최소 28칸 다르다. 이는 모바일에서 조작하기 어려운 짧은 재단을 줄인다. 재료가 6% 이상 제거되는지도 확인한다.

후보를 최대 8번 검증한 뒤 실패하면, 높이 84칸의 수평 절단 하나와 윗조각 제거로 구성된 고정 기본 문제를 검증해서 반환한다. 따라서 운 좋은 난수를 기다리는 무한 재시도가 없다. 기본 문제의 동일한 해법이 모든 uint32 seed에 대해 존재한다. `generate(seed, 0)`은 이 경로를 직접 실행한다.

## 스테이지와 함께 만드는 증명서

문제에는 구간 경계·벽 높이, 유한한 재단선 목록, 제거할 면의 내부 클릭 좌표, 목표 재료 마스크가 있다. 검증은 다음 순서로 수행한다.

1. 입력 범위와 합법적인 수평·수직 재단선인지 검사한다.
2. 재단선을 정수 직사각형으로 만들고 독립적인 DFS로 면을 찾아 클릭 순서대로 제거한다. 게임의 Bresenham 선 래스터화와 BFS 영역 분할을 이 계산에 사용하지 않는다.
3. 남은 모든 열이 벽 아래에 있는 연속적인 아래쪽 재료인지 검사한다.
4. 실제 게임의 영역 분할·제거 함수로도 같은 동작을 재생한다. 독립 계산과 **전체 78,400개 재료 비트가 같은지** 비교한다.
5. 이 실제 결과를 목표 마스크로 사용한다. 따라서 증명된 해법은 게임의 모양 점수 1을 얻는다.

`proof.minima`는 각 열에서 남은 재료가 시작하는 행이다. `materialHash`는 디버깅용 FNV 식별자이며, 해시 비교가 증명을 대신하지 않는다. 검증기는 절단·제거 결과 자체를 검사한다.

## 삽입 경로가 안전한 이유

아래쪽을 양의 y 방향으로 잡는다. 열 x의 벽 끝 높이를 h[x], 남은 재료의 첫 행을 m[x]라고 하자. 검증기는 모든 열에 대해 다음을 확인한다.

```
h[x] <= m[x] <= 144
남은 재료 = 각 열의 [m[x], 280) 구간 전체
```

타일을 목표보다 아래로 d만큼 옮겼을 때(d ≥ 0), 재료의 모든 점은 다음을 만족한다.

```
y + d >= m[x] + d >= h[x]
```

따라서 목표와 x가 같은 시작 위치에서 수직으로 끌어 올리는 **연속 경로 전체**가 벽 내부와 겹치지 않는다. 몇 개 지점만 검사해서 추측하는 보장이 아니다. 모든 열이 144행 이하에서 시작하므로 공통 아래쪽 띠도 남고 타일은 한 덩어리로 연결된다.

이는 최초 상태에서 적어도 하나의 해법이 존재한다는 보장이다. 플레이어가 잘못 자른 모든 상태에서 계속 풀린다는 보장은 아니며, 되돌리기·다시 시작으로 복구한다.

## 게임 물리와의 연결

재료 비트 하나는 점 하나가 아니라 **1×1 칸 전체**다. `rectangles()`는 재료를 손실 없이 직사각형 합집합으로 바꾼다. 충돌 계산은 재료 한 칸을 256단위로 나눈 정수 좌표에서 수행한다. 벽에 경계만 닿는 것은 허용하고 면적이 겹치면 충돌한다.

`move()`는 x 이동 후 y 이동 각각에서 첫 접촉까지의 거리를 계산하므로 빠른 포인터 이동도 벽을 뚫지 않는다. 벽을 따라 미는 동작을 허용한다. 자동 맞춤 전에 `sweepFree()`로 이동 중의 전체 영역을 확인한다. 수직·수평 이동에는 정확하며, 대각선 맞춤에는 경로를 포함하는 직사각형을 검사하므로 가능한 이동을 보수적으로 거절할 수 있다. 안전하지 않은 이동을 허용하지는 않는다. 증명된 수직 진입은 이 제한에 걸리지 않는다.

화면별 `layoutProof()`는 원본 타일의 시작 위치가 벽 아래인지, 시작/목표의 x가 같은지, 증명된 재단을 자 길이와 위치 제한 안에서 그릴 수 있는지, 잡을 재료와 경로가 화면 안에 있는지를 확인한다. 너무 작은 화면은 플레이를 잠시 멈추며, 충분한 세로 공간이 생기면 같은 문제로 복귀한다. 회전·리사이즈는 진행 중인 드래그를 취소하고 자동 맞춤 위치도 새 레이아웃에 맞춘다.

## 검증과 한계

```
node tests/tile-fit-generation.cjs
node tests/tile-fit.cjs
```

생성 검사는 1,024개 seed의 독립 재단 검증, 전체 삽입 경로, seed 재현, 변조된 해법의 거절, 강제 기본 문제, 재료 직사각형의 정확한 복원, 얇은 벽 관통 방지를 확인한다. 정수 이동기는 1,000개 사례를 별도의 전수 단위 이동 계산과 비교한다.

입력 검사는 실제 게임 스크립트에 자 몸통 이동·손잡이 회전·펜 드래그·조각 탭·타일 연속 드래그를 입력한다. 여러 세로 화면 크기에서 해법을 재생하고 벽 충돌, 시작 연출, 자동 맞춤, 제거 미리보기, 스냅, 새 문제·초기화, 작은 화면 복귀와 맞춤 중 리사이즈를 확인한다. DOM과 캔버스는 모의 객체다.

알고리즘의 보장은 위의 정수 재료 모델과 생성 범위에 대한 것이다. 유한한 seed 테스트만으로 모든 seed의 성질을 주장하지 않으며, 그 부분은 생성 제약·검증 조건·수직 진입 부등식과 고정 기본 문제로 설명한다. JavaScript 구현 전체의 기계적 형식 검증은 아니다. 화면 렌더링·포인터 입력은 부동소수점 좌표를 거치며, 실제 휴대전화의 사용감·브라우저 렌더링·멀티터치는 별도 확인 대상이다. 이번 변경은 브라우저 연결 도구를 사용할 수 없어 새 시각 검증을 수행하지 못했다.

설계 근거와 1차 자료는 [앞선 조사](random-stage-generation.md)에 기록했다.
